# Codex 账号、历史与环境配置（0.10.0）

本版重排 Codex 管理 UI 和存储操作；Claude Providers 的布局保留，网络实现改为覆盖插件及正常 CLI 的独立配置。扩展 ID 不变。历史浏览交给官方 Codex Chats；ModelSwitch 不再列出、搜索或预览聊天正文。

## 界面与操作顺序

插件显示名称为“AgentDeck”，原内部扩展标识及数据键保持不变。界面默认中文，保留 Codex、Claude Code、API、HTTP、JSON、模型 ID 等专有名称或技术表达。

Codex 页面按“总览 → 数据与存储 → 网络设置 → 账号与 API”排布。账号与 API 内包含登录方式、官方账号和 API 供应商。主模块、子模块使用统一的折叠边框；说明在标题下，固定注意事项以“ⓘ 注”区分。总览突出当前环境，配置按钮和终端按钮并排；配置管理开关不等于禁用官方扩展。

官方模式下 API 配置只读，API 模式下官方账号只读。账号切换、模式切换、活动历史绑定和实际网络设置变更显示持续待重载状态，成功后提供原生重载入口。每次启动做本地轻量核查后再清除；不扫描全部聊天或自动测速。API 内切换供应商的提醒保留约一分钟，也可手动关闭；只改模型不新建颜色提醒。

操作结果显示在对应模块或供应商上方，绿框成功、红框失败，十秒后消失；每个目标独立计时，新结果不会被旧计时器移除。文件恢复未完成的持续错误不受十秒计时影响。测试或单个供应商结果更新时保留其他卡片和未保存表单。

每个 API 供应商分别提供模型列表刷新、选择模型和真实验证；诊断分连接/模型目录/可选额度与三轮生成速度。首轮数据和三轮汇总分开，缓存、缓冲和失败状态仍保留。批量诊断可选择供应商，默认不发生成请求；消耗额度的测速显式选择。官方账号诊断仅查询当前账号的模型和额度窗口，或执行当前账号三轮测速，不切换其他账号。

顶部刷新只更新当前安装版本的状态，不会替其他容器安装新版。网络实现和 Linux 实验入口的兼容性限制见 [网络说明](network-proxy.md)。

## API 群组与共享历史

供应商群组、模板、排序、禁用及新版配置格式见[客户端架构与群组](client-architecture.md)。所有 API 供应商仍使用唯一 API 历史档案，与群组无关。已连接数据目录后，在“账号与 API → 登录方式”点击“切换到 API”，自动创建或复用 API 档案，重载后应用供应商。另一环境连接同一目录时选择已有 API 档案，再重载及应用本环境供应商。当前新增档案默认名为“API 共享历史”；旧名称或用户别名保留。

## 存储结构与 CODEX_HOME

用户选择 `ai_client_data`，插件使用它的 `codex` 子目录；直接选择名为 codex 的目录也可以。

```text
ai_client_data/codex/
  readme.md
  profiles.json                         共享账号档案注册表，不保存活动选择
  profiles/home-<UUID>/history/
    sessions/                           共享原生聊天文件
    archived_sessions/
    sqlite/                             共享原生 SQLite 状态/索引
  providers/                            用户主动导出的公共定义
  environments/<环境UUID>/
    logs/                               本环境操作日志（自动轮换）
    binding.json                        本环境活动档案
    homes/<档案UUID>/
      config.toml                       本环境、该档案的配置
      auth.json                         本环境、该档案的登录缓存（登录后生成）
      sessions -> 对应共享历史目录
      archived_sessions -> 对应共享归档目录
    .recovery/current/                  仅操作期间存在；异常冲突时保留
  backups/codex-history-<UUID>/          用户主动备份
```

实际 `CODEX_HOME` 在 Linux 下若已是普通目录（包括 bind mount），保持根目录原位，只替换其中的历史子目录链接；入口原本是链接或尚不存在时，继续链接到本环境的账号 home。固定入口的 auth.json/config.toml 使用普通文件，切换时事务保存当前缓存并加载目标档案缓存，以兼容 Codex 原子替换认证文件。删除认证后再切回也不会恢复旧凭据。没有设置 CODEX_HOME 时使用当前执行端默认 `~/.codex`。用户自定义路径也可绑定。应让官方扩展与 CLI 的启动环境一致；在某个终端临时 export 不会更改已运行的 VS Code 扩展进程环境。

历史目录链接让后续新聊天直接写入共享存储，不是后台复制或两份同步。`sqlite_home` 写入每个环境自己的 config.toml，使用该环境看到的挂载路径，并覆盖 CODEX_SQLITE_HOME；应用 API Provider 时保留该路径。history.jsonl/session_index.jsonl 的原始副本随初次迁入保留，当前环境后续的辅助文本索引可各自维护；原生 Chats 的共享数据以 sessions/archived_sessions 和 SQLite 为准。

Linux 创建目录软链接；Windows 本地目录使用 junction。两端路径可以不同，但必须对应同一个物理目录。Windows 开启“让 Codex 运行于 WSL”时，应在对应 WSL 窗口运行本插件，Windows 端会阻止修改错误的 home。Windows UNC/网络共享不保证能创建 junction；失败明确提示并恢复入口，不自动换一种未经验证的共享方式。数据库不能通过云盘逐文件实时同步替代可靠挂载。跨 Windows/Linux 的绝对项目路径、数据库路径与文件锁兼容性仍需实机验收；列表可见不代表另一个环境有原项目工作目录。

## 总览路径与网络核查

总览的“配置位置”显示 Codex 实际读取的运行文件。例如默认入口为 `/root/.codex/config.toml` 时，连接共享数据目录后仍显示此路径，属于正常状态。数据与存储显示用户选定的完整数据目录；历史链接让新聊天直接写入那里，本环境的配置和认证缓存由插件按档案管理。

启动核查只检查本地设置、启动入口、绑定和恢复记录；不自动发出联网或模型请求。若独立 Codex 启动命令的注册丢失或被外部覆盖，显示核查异常，不自动覆盖用户设置，也不将待重载状态清为正常。

“测试连接”检查表单中代理到公共 HTTPS 页面是否可达，不会应用草稿，不等于官方账号登录或聊天生成通过。结果只保留在当前插件运行期间，重启后明确显示尚未测试。旧网络配置需要用户确认后重新应用并重载；普通刷新或重装不会自动迁移。

## 认证、环境识别和共享范围

| 数据 | 范围 |
|---|---|
| 官方账号档案、sessions、归档与 SQLite | 同一物理目录中，同一档案跨环境共享 |
| API 历史 | 所有 API Providers 使用同一档案 |
| config.toml、auth.json、当前账号、CLI 文件、网络设置 | 环境独立；账号配置与缓存进一步按档案独立 |
| Provider 定义/顺序及原 API Key 引用 | 保留原 globalState/SecretStorage；仅 Provider 列表参与 Settings Sync |
| providers/ JSON | 手动导出，不是第二个自动同步的配置源；不读取 SecretStorage 中的 API Key 或用量令牌，不包含认证和聊天；包含经过标准认证字段脱敏的模板、协议高级参数和用量配置。两个 Codex 导出入口格式相同，区别只有保存位置 |
| backups/ | 主动历史快照，排除认证与客户端配置，不自动循环创建 |

新环境首次绑定已有官方档案不复制任何其他环境的认证或配置，需自己登录。原环境重启/重连通过原环境 UUID 和账号 home 复用缓存；过期仍由 Codex 要求登录。文件凭据存储用于本环境隔离；组织强制 keyring 等策略可能限制此方式，需按官方策略处理。环境 UUID 使用扩展运行端磁盘 marker，结合 remoteName/hostname/home/OS；不是每工作区新建。若完整复制扩展存储和相同 hostname 等全部环境身份，将被视为同一逻辑环境；不要以这种克隆方式隔离认证。

绑定同一档案是用户显式选择，不是仅凭登录账号自动寻找任意磁盘中的聊天。其他环境新增档案/Provider 后点刷新可见；它们切换账号不改变本环境绑定。安装新 VSIX 后其他环境仍需各自安装相同新版；刷新不会分发扩展代码。

## 运行设置的操作确认

0.8.1 移除扩展/CLI 的运行中、空闲、未知检测，不再扫描进程或依赖 Codex 私有任务状态接口，也没有重试检测/两次强制流程。官方扩展后台进程存在不等于任务运行。

切换账号/官方/API 模式、应用 Provider/当前模型、改变协议转换代理、应用或恢复网络设置、启用/停用 Codex 管理、连接/迁移目录或恢复历史前，统一弹出一次确认。取消不执行该次运行设置更改；“保存并应用”先确认再保存。提示明确涉及当前环境的扩展和 CLI，请用户先等待任务结束，插件不会自动停止任务。查看、刷新、备份、导出以及单独保存 Provider 定义不额外询问。删除日志/Provider 保留各自删除确认。

用户确认不能消除其他进程同时写入的风险，也不能使现有客户端立即读取新配置。配置/绑定修改后按提示重载或重启。当前主要验收场景是跨环境接续使用，同一 SQLite 跨系统同时写入的兼容性仍需实机验收。

## 操作日志

即使尚未选择数据目录，也从插件启动开始记录。默认位置是当前扩展运行端的 `globalStorageUri/environments/<环境UUID>/logs`（VS Code 扩展存储，不是项目目录）；“数据与存储 → 操作日志”显示完整路径。该路径跨工作区/窗口重启保持；容器销毁且扩展存储未挂载时不会保留。

连接数据目录时，将此前操作日志复制并校验到 `ai_client_data/codex/environments/<环境UUID>/logs`，再持久化位置并删除已验证的旧副本。复制、校验或位置保存失败时原日志及原位置保留；账号目录绑定失败时也尝试恢复原日志位置。若另一窗口仍在旧位置写入，保留其源文件，待该窗口点击刷新状态后校验迁入；不删除活跃写入者唯一的新记录。意外退出可能留下重复校验副本，优先保留数据。

日志记录时间、插件版本、环境 UUID、操作编号/类型/区域、开始与结果、耗时、HTTP 状态等结构化元数据，以及错误类别、系统错误码、插件源文件位置和恢复结果。不会序列化完整操作参数、API Key、OAuth token、认证文件、请求响应正文或聊天内容。为避免服务端错误回显敏感内容，原始错误正文仅在操作区域显示，文件日志保留分类和代码位置。每文件约 2 MiB、操作日志总量约 10 MiB，旧文件轮换。

提供查看当前日志、顶部列表浏览、导出诊断及红色删除按钮。文件由插件直接在 VS Code 编辑器中打开，不调用远程 OS 文件管理器或更换工作区。删除确认只针对当前环境的操作日志和本窗口 VSCodeModelSwitch 输出日志，不删除配置、账号、聊天、备份或恢复材料。本次删除完成记录会成为新日志。旧版 VS Code 输出通道日志仍由 VS Code 管理；新操作日志不依赖输出通道是否打开。

## 失败恢复与迁移

Codex 不再每次 Apply 都生成 vscodemodelswitchbak。先准备完整内容，持久化本次旧文件和变更记录，再逐项替换；普通失败恢复文件、目录链接与活动绑定。成功标记后清理临时恢复点。旧配置存在/不存在的状态均保留，敏感文件使用私有权限；不会回退或覆盖新聊天。

进程异常退出后，下次启动检查恢复记录。其他进程改动了目标内容时停止覆盖、保留恢复材料并明确提示。恢复不完整会锁定后续 Codex 写入；操作确认不能绕过未解决的文件冲突。注册表编辑也使用持久恢复记录，活跃操作不会被另一个窗口回滚。该机制用于应用异常与进程退出，不能承诺任意断电、磁盘损坏或并发外部写入下完整恢复。

首次迁入 Linux 固定目录时，原历史子目录保留在 `CODEX_HOME/sessions.before-vscodemodelswitch-*` 等同级位置，原认证与配置保留在本环境的 `original-home-*` 私有初始副本中。旧的可替换根入口路径仍会保留整个 `CODEX_HOME.before-vscodemodelswitch-*`。这些首次迁入副本不是持续备份，验收后由用户决定是否清理。若历史子目录自身也独立挂载，无法重命名时明确报错并回滚，不修改挂载。旧版环境独占 identities.json 只在“连接/迁入目录”显式升级：可将当前环境的旧账号档案迁入空目标，各旧目录保留；不读取其他环境的认证。目标已有档案时只连接所选档案，不覆盖、不自动合并当前旧历史。旧版全局目录设置不会自动采用，用户需明确选择。已有 vscodemodelswitchbak 不自动删除；Codex 与 Claude 的新应用操作均使用短期恢复记录，不再持续生成该备份目录。

历史备份每次生成新的独立完整快照，不删除旧备份，不做增量或去重。浏览/删除入口列出档案、时间、大小和完成标记；未完成材料也可明确选择后删除，不操作活动历史。当前 UI 不提供恢复为新档案，用户可直接让 AI 读取备份聊天文件。目录内 readme.md 随首次初始化生成，已有说明文件不会被升级自动覆盖。

连接失败可能已完成档案准备，但尚未启用绑定。重试同一数据目录时选择已准备的账号即可；不会清空、重建或自动合并原历史。失败后继续在原目录产生的聊天仍保留在原历史子目录的首次迁入副本中，未自动进入之前已准备的共享档案。请勿删除旧目录，待确认账号和历史范围后再单独处理。

“另存为供应商配置”和“保存到数据目录”均只导出 Codex API 定义，不保存聊天或已存储的密钥。Codex 页面导入只更新 Codex 定义，不修改 Claude、不自动改变当前选择或写入客户端文件。历史备份、Provider 导出/导入、日志操作和输出位置本身不需要重载；改变当前活动绑定才需要。

## 验收与证据边界

自动检查使用合成双环境、合成认证与 JSONL，覆盖独立缓存/配置、共享历史、API 单例、重连与迁移、故障注入/异常退出/外部冲突、单次操作确认/取消、日志迁移/回滚/删除及模块局部 UI 反馈。可选 test:native-history 在隔离 HOME 中启动已安装官方二进制，只调用初始化、thread/list/read，不登录、不发模型请求；移除原环境后验证另一环境能列出并打开历史。它不替代真实 VS Code 界面、真实登录、Windows junction 或跨系统挂载验收。

### 弹窗语言

AgentDeck 自身的确认框、删除/取消按钮、目录选择按钮和进度说明使用中文，不依赖 VS Code 当前语言。已知配置错误显示中文解释；未知服务/系统错误配中文说明并保留“错误详情（原文）”，操作日志继续按原有脱敏规则记录诊断分类和位置，不新增错误正文。VS Code 自带的进度条取消按钮、窗口外壳等系统控件由编辑器语言决定，插件不修改全局语言设置。取消、关闭和按 Esc 均不授权修改。

### 总览网络状态

“旧网络配置，待重新应用”表示当前工具还保留旧代理应用记录。请在网络设置检查地址，结束运行任务后点击“应用更改”、确认并按提示重载。测试连接与安装升级不会自动做这一步；“独立路由配置”表示新版应用标记，实际聊天仍需在客户端验收。“配置核查异常”时请查看网络模块的错误说明。网络三个操作位于状态徽标正下方。
