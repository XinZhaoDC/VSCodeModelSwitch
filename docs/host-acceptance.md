# 宿主机 Codex 验收与跨环境历史

本轮容器验收只覆盖 Codex。自动化夹具、原生 Codex 进程和真实 VS Code 窗口是三类证据，不能相互替代。宿主机请安装同一版本；本轮仓库更名和补充文档不改变 0.10.0 的运行代码。

## 先准备，不切换真实账号配置

1. 容器暂时不要新增聊天、切换档案或更改存储目录。由用户在容器 Chats 选择两三个不敏感的旧会话作为样本，记下标题和大致时间。
2. 宿主机登录与容器相同的官方账号。认证在宿主机完成，不复制容器的 auth.json 或认证缓存。
3. 确认两端选择的是**同一个物理共享文件夹**。容器路径 `/home/workspace/Forest_Interface/ai_client_data` 与宿主机路径可能不同，不能直接照抄路径。
4. AgentDeck 连接该目录时选择**已有的相同官方账号档案**，不要创建同名新档案。账号名称只是本地别名；插件不会根据云端账号自动合并不同档案。
5. 提交确认前结束当前环境扩展和 CLI 的运行任务，完成绑定后按提示重新加载窗口。已有历史不应被删除或重建。

## 验收表

| 项目 | 操作 | 应有结果 |
| --- | --- | --- |
| 安装与环境 | 查看版本和总览 | 显示 AgentDeck 0.10.0；宿主机和容器的环境身份不同 |
| 历史绑定 | 查看绑定、目录链接和索引位置的安全元数据 | 两端指向同一已有档案；运行配置和认证缓存分属各自环境 |
| 官方 Chats | 选择“全部聊天”，查找上述样本并打开 | 两端都能显示、读取样本；当前项目筛选不能被误判为丢失历史 |
| 归档 | 对已有归档样本查看归档列表 | 归档状态与共享数据一致，不为测试删除或改写旧会话 |
| 重连 | 重启宿主窗口、重新连接容器 | 各自仍绑定原档案，历史可见，各自认证状态不被另一端覆盖 |
| 选择隔离 | 两端刷新状态 | 不改写另一环境的账号/API选择、配置、网络或启用状态 |
| 群组 UI | 官方模式查看 API 区 | 能查看、折叠；写操作只读。不要为了这一步擅自切 API |
| 提示与布局 | 展开模块、查看日志、做只读刷新 | 中文提示出现在对应模块上方，普通反馈十秒消失；不跳到顶部 |
| 独立网络 | Linux 宿主显式应用正确代理入口并重载后验证 | 实际 Codex 可联网；单独的连接测试通过不能替代聊天验证 |

API 历史另有一个共享档案，与官方账号历史分开：两端连接同一数据目录、选择同一个“API 共享历史”档案后，本环境可使用不同供应商；供应商群组不会分割聊天历史。真实 API 验收需要用户另行确认模式切换和模型调用，不能在上述官方账号验收中自动执行。

**平台限制：** 独立 Codex 网络入口目前仅实现 Linux，Windows 原生与 Windows/WSL 混合窗口未验收。跨 Linux/Windows 的文件路径、目录链接、SQLite 索引和项目筛选可能影响官方 Chats，需要实机验证；不能据容器夹具直接承诺两端列表完全一致。不要在 Windows 上直接注册 Linux 启动脚本。

```text
不要自动切换 API、调用付费模型、变更 VPN、系统代理或其他插件配置。
输出逐项通过/失败/未验证、可脱敏复现步骤及证据位置，不把未做的项目算作通过。
```
