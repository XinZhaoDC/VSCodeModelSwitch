## 2026-11-11：0.8.1 后续网络隔离与存储说明审查

状态：设计核对；未修改运行实现、未构建新版本、未安装、未更改实际网络配置。既有 0.8.1 测试证据不能证明下述新网络方案已经实现。

### 当前实现的实际范围

- `src/network/manager.ts`：Codex 应用网络设置会修改 VS Code `http.proxy`；远程端还设置 `http.useLocalProxyConfiguration=false`，本地端为 `http.proxy` 增加 Settings Sync 排除。它还修改当前扩展宿主进程的 `NO_PROXY`、`no_proxy`，因此不能宣称只影响 Codex。
- Claude 页面修改 `claudeCode.environmentVariables` 中 HTTP(S)_PROXY、NO_PROXY 的大小写六项，保留其他项目。原生入口是 Claude 进程，不是整个终端或系统环境；Claude 启动的子进程仍可能继承这些变量。Codex 对共享宿主环境的修改也使旧方案并非完全隔离。
- ModelSwitch 自身的模型、诊断与兼容转发请求通过工具标识选择网络配置；这与原生聊天客户端的启动方式是两个不同环节。测速成功不能证明原生客户端已经采用相同路由。
- `restore()` 保存并恢复所接管字段，但部分失败回滚仍吞掉单项恢复错误，缺少完整的恢复后核实。后续需要报告部分恢复失败，保留可重试材料。

### 新实现要求与入口限制

目标：Codex 与 Claude 分别使用自己的路由配置；不写共享 VS Code HTTP 代理、不修改扩展宿主 `process.env`。配置与恢复按工具、运行环境分开；同一工具的后台进程和由其继承环境的子进程是预期影响边界。

当前安装的 OpenAI 扩展 `openai.chatgpt-26.1007.21434-linux-x64` 将 `chatgpt.cliExecutable` 声明为 `scope: application`。其启动器直接使用该值作为可执行文件路径。官方将其列为开发用途。VS Code 的 application 配置不能由远程设置覆盖，因此不能将“每个环境分别写入一个绝对启动脚本路径”当作已经可用的宿主机/容器隔离方案。

专属启动程序仍是候选，但须先验证配置入口的跨环境分发及启动时序，再接入 UI；不能回退到共享 HTTP 设置并声称隔离成功。不得自动替换用户已有的自定义启动程序。外部浏览器登录、VS Code 自身流量不包含在后台进程代理的保证范围内。

### 三种现有备份/导出

1. 历史备份：`src/sessions/codexHistory.ts` 复制所选档案的会话 JSONL、归档会话、历史/列表索引及 SQLite 索引相关文件，生成校验 manifest，保存在当前数据根的 `backups/`。不复制 `auth.json`、`config.toml`、Provider 定义、工程源码或 VS Code 设置。复制前后校验不是在线数据库备份协议；应避免写入聊天，变化时报告失败并保留不完整材料。
2. `Export`：`src/app.ts::exportPublicConfig()` 保存两工具的完整 Provider 元数据及当前选择 ID 到用户选择的 JSON 文件；不读取 SecretStorage 中的 API Key 或用量令牌。包含名称、URL、模型策略、配置模板、协议处理和用量设置等已保存元数据，不包含聊天及官方登录缓存。当前 `Import` 可改变两工具定义及当前选择，不能称为 Codex 专属导入。
3. `Export to data folder`：`exportCodexProviders()` 仅导出 Codex API Provider 的精简字段到当前数据根的 `providers/codex-public-<时间>.json`；不含 SecretStorage 密钥，也不包含完整模板、用量配置及协议处理高级参数。因此旧版两个导出按钮并非仅保存位置不同。

约定改为同一份 Codex Provider 导出格式的两个目标位置：指定文件或当前数据目录。Codex 页面导入不触碰 Claude 的定义和当前选择，不自动应用到客户端。实现前仍按以上旧版事实解释。

### 重载与启动核查约定

- 启动时自动做本地轻量检查：当前环境、当前配置、受管启动入口、活动档案和目录链接、未完成恢复记录。避免自动测速、联网验证、扫描全部聊天或全量历史哈希；挂载不可用应显示可重试状态，不阻塞整个界面。
- 创建历史备份、修改备份输出位置、导出/导入 Provider 定义、修改导出位置、移动/删除日志，以及恢复到未激活的新档案，不需要重载。
- 切换到恢复档案、改变活动历史绑定、切换官方账号或官方/API、改变实际网络启动设置，需要持久待重载提醒；重启后自动核查，异常不得清成正常。
- API 到 API 的 Provider 切换使用限时、可关闭提醒；只更改 API 模型使用普通操作结果，不改变模块边框。保存未使用的预设不产生待重载状态。
- 旧版 API 历史恢复在已有单一 API 档案时拒绝恢复，不能将恢复误报为需要重载即可解决。后续改进应优先支持恢复为不立即激活的材料，明确激活/合并边界；当前没有覆盖恢复或自动合并功能。

## 2026-11-11：网络作用范围、Claude 全覆盖要求与备份术语澄清

状态：源码与官方文档审查；本轮未更改运行实现或网络配置、未运行网络测试。此处补充最新用户要求，不把尚未实现的隔离列为已有能力。

- “扩展宿主”指运行扩展的 VS Code 进程，不等于物理宿主机。容器中该进程的 `process.env` 改动不会反向修改其他进程或 Linux 系统全局环境，但会影响同一进程及后续继承变量的子进程。VS Code 设置修改、进程变量修改与操作系统网络配置修改是三件事。
- 旧协调结果 `Forest_Interface/.ai/results/HO-20261028-001-result.md` 最终验收记载当前方案使用 host-network。若仍保持此前网络模式，宿主和容器共享网络命名空间，因此可以通过同一个 `127.0.0.1:12000` 访问代理；不能套用 bridge 容器回环隔离的解释。本轮没有访问 Docker socket、网络命名空间特殊文件或重新验证容器模式。
- VS Code 的“本地”指桌面客户端侧，“远程”指所连接的容器/SSH/WSL 运行端，不要求物理上是另一台电脑。设置继承是读取配置的优先级规则，不是把环境变量、认证或所有文件复制到容器。共享 host 网络并不消除这个客户端/运行端区分。
- 最新 Claude 要求包括扩展、CLI 及相关子进程的出网约束。当前 `claudeCode.environmentVariables` 不是任意终端的 CLI 设置；`openClaudeTerminal()` 只给 ModelSwitch 新建的终端显式注入变量，且不能证明 shell 初始化脚本未覆盖变量。标准用户级 Claude 设置可以覆盖更多正常入口，但仍不是网络强制隔离。
- 代理变量依赖各程序遵守；任意工具、MCP、SSH 或外部浏览器不能仅凭父进程变量宣称全覆盖。严格目标还须具备“仅允许代理出口、其余外网连接拒绝”的进程网络隔离，并让受管扩展后台及 CLI 入口进入该边界。独立启动且未进入边界的进程不在保证范围内。代理故障时必须验证没有外网直连回退；本地通信例外需明确，不能用过宽绕过列表代替限制。
- 此严格层属于新的网络执行范围：尚未实施或验证，不自动修改当前共享 host 网络、VPN、防火墙，也不能宣称代理路由能保证账号不被限制。
- Provider 两个导出入口的新名称确定为“另存为供应商配置”和“保存到数据目录”，目标使用同一格式；尚未修改现有按钮实现。
- 当前历史备份每次生成新的 UUID 目录，是独立完整快照：不先删除旧备份，不自动增量或去重，不包含认证。恢复为新档案是创建一个未激活的历史副本，不是创建新的官方账号；使用时再切换绑定并重新加载。原档案保留，当前不自动合并历史；已有 API 档案的恢复限制仍按前文记录。
