# 客户端模块与供应商群组（0.10.0）

这是当前实现的维护入口。AgentDeck 仍是一个 VS Code 扩展，内部扩展标识和现有数据键保持。没有实现 WorkBuddy 的真实设置、网络或历史适配。

## 源码职责

- `src/clients/index.ts` 是内置模块组合入口；`shell/clientRegistry.ts` 注册客户端标识、名称、能力、消息处理器和页面贡献。导航从注册表生成，不把页面入口限定为两个工具。
- `clients/codex/` 拥有页面布局、群组操作、账号/历史、原生配置适配及官方诊断/测速；`clients/claude/` 拥有 Claude 页面、操作入口及其配置适配器。已有文件移动后只更新模块引用，不改变运行配置目录。
- `shared/clients/providerController.ts` 复用供应商/网络等公共操作分发，Codex/Claude 控制器的依赖接口分别收窄。消息里的工具和供应商归属在后台核对；Claude 不能调用 Codex 历史或群组操作，未知操作不会空执行后显示成功。
- `shared/providers/` 负责群组元数据、导入计划和本环境可用性；`shared/ui/` 复用请求处理字段；文件恢复、日志、传输和现有 API 协议服务继续复用。`app.ts` 保留扩展生命周期、命令与这些服务的协调接口；它不是第三客户端必须实现的接口。
- 两个已有页面复用同一个表单组件，但各自持有内存草稿；页面切换不把供应商名称、密钥、模型和请求参数带到另一页面。密钥草稿不写入 webview 持久状态。网络草稿、折叠、操作提示及禁用状态有各自客户端/环境范围。

## 接入新客户端

新建 `clients/<client-id>/`，实现注册表 `ClientModule`：唯一字符串 ID、名称、能力、`handle`，以及可选浏览器页面 `browser`。在组合入口注册。独立页面提供 `markup`、定义页面类的 `script` 和 `controller` 类名；`render(state, busy)`、`enter/leave`、`receive` 是页面生命周期约定。用 `clientAction` 携带该客户端自己的操作与数据，处理器可以回复自己的状态，不需要借用 Codex/Claude 的专属操作。

新增页面的控件 ID 使用 `<client-id>-` 前缀，控制器类名唯一；注册时检查，避免遮蔽公共按钮。浏览器代码与页面贡献是仓库维护代码，不加载任意外部脚本。现有 `ToolId`/协议适配类型描述当前两个内置 API 适配器，并不限制注册表客户端 ID；新客户端若复用 Provider/网络后端，应为其补齐协议和配置适配，不能把它当成 Codex 或 Claude 去写文件。没有动态插件加载、占位 WorkBuddy 功能或一套额外依赖框架。

## Codex 群组和排序

默认群组“独立供应商”初始排第一，之后可移动。允许空群组。群组名在 Codex 内唯一；供应商名在整个 Codex 内唯一，跨群组也不能同名。名称比较忽略首尾空白、英文大小写和 Unicode 全半角差异。Claude 的名称空间独立。

标题的拖动手柄调整群组顺序；供应商的手柄支持组内排序和跨组移动，“移动到群组”提供选择列表。启用与禁用分区分别排序，禁用项目总在末尾；恢复后重新按已保存顺序排列。群组折叠状态按环境保留。移动只改变归属/顺序，不改连接、模型、Key 或实际客户端文件。

单个供应商禁用后只保留恢复和原组排序；所在群组禁用后，组内配置/模型/用量/测速/协议操作都不可用，但仍可查看、排序及接收新的供应商。群组恢复不改变成员各自标记。当前供应商禁止单独禁用；禁用包含它的群组要求确认，并明确当前 Codex 继续使用已应用配置，不切换、不停止、不撤销 Key。该状态仍在群组和总览可见。禁用是 AgentDeck 的本环境操作限制，不是服务器账户停用或进程出网拦截。

## 模板与网络

请求处理模板库支持命名新建、载入编辑、保存、删除。群组可以从库复制请求处理设置，也可以另存为新模板。群组还可保存默认 API 地址；密钥、账号模型和额度设置仍在供应商上。

载入是显式复制：改库不会改已保存群组；改群组不会改成员；移动不载入。添加表单的“载入群组模板”只填草稿；现有供应商的同名按钮只填入配置编辑器，用户检查、保存后再明确应用。删除模板不破坏已载入副本。

群组的网络设置只引用当前环境已保存的 Codex 网络预设名称，不把具体 VPN 入口放进共享模板。群组按钮“载入本组网络预设”只填网络草稿，必须在网络模块明确应用和重载才生效。供应商切换不会静默切换群组网络，更不会影响 Claude 路由。

## 持久化与导入导出

- 原 Provider 列表与密钥引用保留。首次没有群组元数据时，现有供应商按默认群组显示；不重建 ID，不改 Key，不写客户端。
- `vscodemodelswitch.organization.codex` 保存群组、顺序、成员关系和模板；它与原 Provider 定义一样属于共享元数据并可参与 Settings Sync。
- 禁用标记和群组网络预设引用在环境命名空间中保存，不参与跨机器同步；当前供应商和真实 CLI 配置仍独立。两个客户端不共用群组命名空间。
- 两个 Codex 导出入口均为 v2 JSON，包含完整群组（含空组）、成员和模板，以及脱敏 Provider 定义；不包含禁用状态、网络入口、认证缓存或 SecretStorage 中的 Key。`providers/` 仍是主动导出目录，不是自动配置源。
- 支持 v1 导入，保留现有群组元数据；新版导入先完成名称、归属和 ID 冲突检查。合并/替换仅作用于当前页面客户端，不更改当前选择或自动应用。定义/群组写入失败尝试恢复此前两份元数据；恢复不完整明确报错，不表示导入成功。
- 导入、群组、排序、禁用和模板保存不要求重载。真正应用网络、模式或历史绑定仍按原有确认/重载规则执行。

## 历史不随 API 群组拆分

所有 API 群组和供应商仍共用同一个 API 历史档案。已有数据目录中，点击“切换到 API”会复用或建立唯一 API 档案，重载后应用供应商。另一个环境连接同一物理目录时选择已有 API 档案，不另建同名目录。官方账号各自的历史保持独立；新环境认证不复制。目录详见 management.md。

本轮原生 Linux fixture 增加 API-A/API-B：不同 API 地址和合成密钥、同一 API 档案，在默认供应商过滤下两环境都列出并读取两条历史，官方历史不混入。不发模型请求；不是宿主机真实图形界面或跨 Windows/Linux 挂载验收。

## 平台和验收

Linux 隔离测试包含第三客户端注册/视图/消息夹具、群组 UI、禁用保护、模板副本、v1/v2 导入及故障恢复。Windows 原生网络启动器仍未实现；WSL、真实账号/聊天/两客户端图形界面和跨OS挂载未实测。没有修改真实代理、账号、绑定或历史。安装后先检查迁移后的原列表，再用空群组/非当前供应商验收拖动、模板和禁用；当前群组禁用确认不停止真实任务。
