## Unreleased - 2026-09-05

### 网络与兼容性诊断

- 将基础网络可达性、Models API、模型协议兼容性和 Usage 查询拆分为独立结果。
- `/v1/models` 或 `/models` 不支持、返回 HTTP 错误时，不再直接判定整个 Provider 网络断开。
- Models API 均失败时，使用 Provider 域名根地址执行基础可达性回退检查。
- 网络结果记录最终端点、HTTP 状态、延迟、响应大小和 DNS 地址。
- 识别远程域名解析到容器回环地址的错误，并将 `198.18.0.0/15` 标记为 VPN Fake-IP。
- Claude 请求优先使用与 `ANTHROPIC_AUTH_TOKEN` 一致的 Bearer 认证；认证失败时兼容回退到 `x-api-key`。
- `Verify Model` 区分网络、认证、端点不支持和请求被拒绝，并参与 Active Provider 的全局状态判断。
- Usage 新增 `Auto Detect`，在同一 Provider 域名下依次尝试常见余额、用户信息、Key 状态和 credit-grants 端点，并匹配多种已知 JSON 结构。
- Auto Detect 扩展 Kimi、StepFun、OpenRouter Credits、Novita、积分余额、账户报表和 New API 数据端点，总查询时间限制为每个 Provider 20 秒。
- Auto Detect 可选使用独立的 Management Access Token 与 User ID 查询 New API/AgentRouter 管理接口；未提供时不会误用模型 key 请求这些管理接口。
- Usage 解析失败只记录 JSON 字段结构，不记录字段值或原始响应正文。
- 新增不记录密钥和响应正文的 `VSCodeModelSwitch` Output 通道，记录网络、Usage、兼容性和模型拉取诊断。

### 状态与执行行为

- 网络及兼容性结果按 Provider ID 保存，避免一个 Provider 的旧错误污染同工具的其他 Provider。
- 仅 DNS、传输层或真实模型验证的网络失败显示 `Network error`；认证和协议失败显示 `Degraded`。
- 修改模型或完整配置、删除 Provider 时清除对应的旧诊断结果并重新匹配实际配置。
- 工具级 `Network & Usage` 最多并发检查两个 Provider，取消操作会同步终止网络和 Usage 请求。
- 单独的 Usage 查询也支持取消。
- Add Provider 的模型控件支持直接输入 Model ID；Models API 不可用时不再阻塞模式 A 添加。
- Fetch Models 支持取消，失败提示和 Output 日志包含候选端点及 DNS 诊断。
- Key fields 模式只要求 Tool、Name、Base URL 和 API Key；Model ID 可留空，拉取成功时自动填入首个结果，失败时显示警告并保留手动输入。
- Provider 卡片与全局 Active 状态中的空 Model ID 统一显示为 `NULL`，且空模型时禁用 `Verify Model`。
- Full Configuration 不再被隐藏的模式 A 必填字段拦截；允许空 model 保存并显示警告，`effortLevel` 可以为空或省略。
- `Set active after saving` 默认关闭，命令面板添加流程也不再自动激活。
- 全局状态区域显示当前扩展日志目录及 Claude/Codex 备份目录大小。
- Claude/Codex 折叠按钮隐藏整个 Tool 面板；Enabled 开关继续作为操作锁。
- Configuration 区域新增带确认的 `Delete Log`，用于删除当前扩展日志目录中的普通日志文件并重建空日志通道。

### 安全与配置

- 未新增代理配置，TUN 模式继续使用容器现有系统路由。
- 未改变 Provider 持久化结构、SecretStorage 引用和实际 Claude/Codex 配置格式。
